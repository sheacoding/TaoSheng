# 声云通用设备插件补齐

## 范围与依据

基于上游 `11fa0b65453808ffe51d0daf8f10816e3a2bd856`（v0.2.21 之后的主线）。按 [维护者 #14 最新回复](https://github.com/0xCoach/TaoSheng/pull/14#issuecomment-6765845917)，沿用已发布的 JSON 说明卡、FileSourcePlugin 与 DeviceSync，不迁入旧厂家 AAR、SDK 依赖、录音卡专用 UI 或 Wi-Fi 进程绑定。

公开协议依据：[声云 BLE 协议 §6、§7、§9](https://github.com/SonicloudTech/sonicloud_opensdk/blob/478e54262e5e2a04f2ab397766065cacbb381e83/pnote-web-win%26Mac-demo/docs/%E5%8D%8F%E8%AE%AE.md)。文件命令 2-2 为 uint32 小端偏移与 24 字节文件名，完整请求一次写入；中断用 2-7 终止；删除用列表原始 28 字节条目。

## 改动

- 启用插件续传能力，发送核心提供的 WAV 字节偏移；拒绝负数、uint32 溢出和无效文件名。保留单次 36 字节请求约束，完整性检查仍使用 WAV 自身 RIFF 长度，而非目录中的压缩大小。
- 设备明确拒绝非零续传偏移时，插件报告通用 ResumeOffsetRejected；由核心清空本地部分文件和持久化进度，在既有三次尝试上限内从零重下。普通断连仍保留进度，零偏移被拒绝仍失败，不引入品牌分支或修改公共契约。
- 下载取消、异常、超时或消费者提前结束时，在清理订阅后以独立限时操作尽力发送终止命令；清理失败不覆盖原始异常。成功下载不发终止。
- 目录缓存只在列表成功后发布，严格检查条目长度、空名称和重复标识。删除必须匹配同一连接及完整文件元数据；成功应答后消耗该条快照。核心原有“安全保存后才删除”门槛不变。
- 原说明卡仍为 trial；核心接口、UI、数据库、版本和依赖未变。原 `feat/sonicloud-recorder` 与三个历史 PR 分支保留作为参考。

## 验证

Windows/JDK 21 下最终 assembleDebug 成功，SonicloudFilesTest 9 项及 DeviceSync120Test 17 项共 26 项通过，0 失败/跳过。首次构建测试 5 分 6 秒；复核补齐偏移拒绝恢复后，只重跑受影响的两套测试并构建，耗时 1 分钟。本轮新增 10 项测试。Standards 与 Spec 两路最终复核未发现未解决的阻断项。未使用厂家 AAR 或本机 SDK init 脚本。新增测试覆盖非零偏移、拒绝偏移后的 0→2→0 完整恢复、偏移边界、协程取消、传输失败、原始删除字节、跨设备/文件变化、目录请求失败和畸形目录；同时运行既有 DeviceSync120Test，覆盖核心持久化、校验、去重、保存先于删除及原始协议帧。

## 真机验收与限制

此前用户确认的是厂家 AAR 路径，不能外推为本次直接 BLE 插件已通过。需要在有备份的测试录音上验证：打开声云试用说明卡、发现与重连、实时声音、WAV 完整导入、下载中断后的非零偏移恢复、取消后重新导入，以及保存成功后的设备文件删除。当前核心全量同步可能自动删除成功导入的设备文件，验收不能使用唯一原件。

本次未修改 Wi-Fi、日期分页等界面；不承诺 AAR 所支持的所有机型都与公开 CB08 协议相同。终止指令只做限时尽力发送，不证明断链设备实际收到；固件对 WAV 非零偏移的行为仍需实测。缺失时钟导致的断开区间补传限制沿用上游实现，未伪造文件修改时间或对时偏差。
